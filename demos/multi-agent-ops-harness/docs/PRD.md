## 1. 背景与目标

### 1.1 问题背景

企业员工多数任务需串联**文档检索、数值计算、结论汇总**，而非单步查文档：

| 任务类型 | 输入示例 | 能力链 |
|----------|----------|--------|
| 制度 + 计算 | 80 万合同延迟 20 天，违约金多少？是否触顶 5%？ | 查条款 → 计算 → 报告 |
| 对比 + 计算 | InsightDoc vs FlowAgent，200 人 3 年成本差 | 查定价 → 运算 → 报告 |
| 制度解读 | 远程 10 天，市内交通能否报销？ | 查制度 → 明确结论 |
| 合规审核 | 跨境采购签约前要完成什么审核？ | 查合规条款 |
| 拒答 | 知识库有没有年假规定？ | 确认无覆盖 → 拒答 |

Demo A 已解决深度文档研究与带引用报告，但固定流水线**不具备数值计算与多 Agent 协作**，无法端到端完成上述复合任务。

### 1.2 产品定位

面向复合企业任务的 **Supervisor 驱动多 Agent 协作产品**。Supervisor 动态派活给 Research（检索）、Analyst（计算）、Reporter（报告）三个专业 Agent。Research 工具 MCP 化，知识库复用 Demo A，形成「Deep Research + 任务编排」能力互补。

**能力边界：** 子 Agent 当前串行执行；无生产级任务队列与权限；MCP 仅对接自研检索工具。

### 1.3 成功指标

| 指标 | 定义 | 目标 | v1.0 实测 |
|------|------|------|-----------|
| 任务成功率 | 12 题封闭集端到端完成 | 100% | 100%（12/12） |
| 期望 Agent 覆盖率 | 所需 Agent 均被调用 | 100% | 100% |
| 多 Agent 协作率 | ≥2 个 Agent 参与 | 100% | 100% |
| 关键词命中率 | 报告命中预期关键信息 | ≥ 85% | 92.4% |
| 计算器调用率 | 计算题调用 calculator | 100% | 100%（3/3） |
| 拒答准确率 | 无覆盖时正确拒答 | 100% | 100%（1/1） |
| 延迟 P50 | 端到端耗时中位数 | Demo 可接受 | ~51s |

## 3. 产品方案

### 3.1 协作架构

```
复合任务 → Supervisor（任务理解与路由）
              ↓ 循环派活
         Research（查文档 → 检索笔记）
         Analyst（基于笔记 → calculator 计算）
         Reporter（汇总 → Markdown 报告）
              ↓
         最终报告 + Agent 时间线
```

| 角色 | 职责 |
|------|------|
| Supervisor | 解析任务意图，派活给子 Agent；规则护栏纠正路由偏差 |
| Research | 查 Demo A 知识库，输出含数字与条款的检索笔记 |
| Analyst | 基于笔记数字调用 calculator，禁止 LLM 心算 |
| Reporter | 汇总依据与计算结果；拒答场景继承「未找到」信号 |

**路由原则：** 含计算意图 → 先 research 再 analyst；需报告 → reporter 汇总；至少 2 个 Agent 参与后方可结束。

**规则护栏：**

| 触发条件 | 强制动作 |
|----------|----------|
| 未检索即结束 | → research |
| 计算题有笔记但未调 analyst | → analyst |
| 未调 reporter 即结束 | → reporter |
| 仅 1 个 Agent 参与 | → 补 research 或 reporter |
| 无笔记即进 analyst | → research |

**计算触发词：** 计算、多少、相差、应付、违约金、成本、年、差、总、上限

### 3.2 与 Demo A 对比

| 维度 | Demo A | Demo B |
|------|--------|--------|
| 任务 | 文档研究问答 | 检索 + 计算 + 报告 |
| 编排 | 固定四节点流水线 | Supervisor 动态派活 |
| 计算 | 不支持 | Analyst + calculator |
| MCP | 无 | Research MCP 化 |
| 知识库 | 独立维护 | 复用 Demo A |
| 延迟 | 30–60s | P50 ~51s |

## 5. AI 质量要求

### 5.1 编排质量

- 计算类任务走完整「检索 → 计算 → 报告」链路
- 至少 2 个 Agent 参与；步数上限防死循环

### 5.2 计算质量

- 必须调用 calculator；数字仅来源于检索笔记

### 5.3 报告质量

- 汇总制度依据与计算过程；拒答不编造

### 5.4 评测体系

封闭评测集 **12 题**，校验成功率、关键词、Agent 覆盖、计算器调用、拒答、持久化。

| 指标 | 目标 | v1.0 |
|------|------|------|
| 任务成功率 | 100% | 100% |
| 关键词命中率 | ≥ 85% | 92.4% |
| Agent 覆盖率 | 100% | 100% |
| 计算器调用率 | 100% | 100% |

**质量边界：** 串行执行，P95 ~187s；长任务体验待 v1.1 优化。

### 7.2 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| Analyst 跳过 calculator | 计算错误 | 护栏 + 评测校验 |
| 检索未覆盖定价段 | 成本对比缺失 | 多轮 research |
| Reporter 编造拒答 | 合规风险 | 信号传递 + 关键词校验 |
| 长任务延迟 | 体验差 | v1.1 并行 |
| 依赖 Demo A 知识库 | 部署需联动 | UI 引导 + 一键加载 |

**关联产品：** Demo A 提供知识库与深度文档研究；本产品承担复合任务编排。
