## 1. 背景与目标

### 1.1 问题背景

中型及以上企业的内部知识分散在制度文件、产品手册、采购规范、合规政策等非结构化文档中。员工在报销审批、合同条款核对、多产品选型、合规审查等场景中，核心诉求是**跨文档综合理解后给出可执行结论**，而非定位单段原文。

单轮 RAG（检索一次、直接生成）在复杂场景存在四类系统性缺陷：

| 痛点 | 具体表现 | 业务影响 |
|------|----------|----------|
| 检索覆盖不足 | 对比类问题只命中单侧文档 | 售前选型、采购比选结论片面 |
| 缺乏自我纠错 | 检索不充分时仍强行作答 | 制度解读错误，合规与操作风险 |
| 结论不可审计 | 回答缺少与原文的精确映射 | 财务复核、法务审查无法追溯 |
| 拒答能力弱 | 知识库无内容时编造制度条款 | 误导员工执行错误流程 |

### 1.2 产品定位

面向企业内部知识库的 **Deep Research 问答产品**。用户输入自然语言问题，系统自动完成检索规划、多轮检索与覆盖评估，输出带 chunk 级引用的 Markdown 研究报告。

采用固定研究流水线（规划 → 检索 → 反思 → 撰写），在灵活性与可评测性之间取得平衡：相比单轮 RAG，增加 Hybrid 检索、Rerank 与反思补检；相比开放式 ReAct Agent，节点路径确定，便于质量评测与过程审计。

**能力边界：** 专注文档研究问答；不承担数值计算与多 Agent 编排（由 Demo B 承担）；当前知识库为 5 份示例文档。

### 1.3 成功指标

| 指标 | 定义 | 目标 | v1.0 实测 |
|------|------|------|-----------|
| Recall@5 | 60 题封闭集 Top-5 引用命中预期来源 | ≥ 95% | 100% |
| 引用准确率 | 正文来源标注与引用列表一致 | 100% | 100% |
| 拒答准确率 | 知识库无覆盖时正确拒答 | 100% | 100%（4/4） |
| 忠实度 | 结论 grounded 于检索片段（启发式） | ≥ 70% | 76.1% |
| 任务完成率 | 60 题全量评测无异常中断 | 100% | 100% |

## 2. 用户与业务场景

### 2.1 目标用户

| 角色 | 部门 | 核心诉求 | 问题复杂度 |
|------|------|----------|------------|
| 普通员工 | 各业务线 | 查制度流程、确认步骤与材料 | 中 |
| 财务/行政专员 | 财务、行政 | 核对报销规则、审批权限、付款时限 | 中 |
| 采购/法务 | 采购、法务 | 查合同条款、违约金、合规要求 | 高 |
| 售前/产品 | 销售、产品 | 多产品对比、场景匹配 | 高 |

### 2.2 业务场景

#### S1 · 流程查询

- **典型问题：** 报销分几步？每步需要什么材料？
- **业务要求：** 输出完整步骤链，覆盖四步报销流程及差旅、采购、招待等材料差异
- **输出要求：** 分点呈现；每步附来源引用；trace 可见规划与检索记录

#### S2 · 跨文档对比

- **典型问题：** 产品 A 与 B 在价格、适用场景上有何区别？
- **业务要求：** 同时引用 InsightDoc 与 FlowAgent 两份手册，从定价、客户、功能三维度对比
- **专项策略：** 识别对比意图，追加定向检索词；反思阶段检查双来源覆盖，不足则补检

#### S3 · 条款解读

- **典型问题：** 采购合同的付款周期与违约金如何规定？
- **业务要求：** 准确提取预付比例、违约金日率、5% 上限等数值，数字须 grounded 于原文

#### S4 · 摘要归纳

- **典型问题：** 用 3 条要点总结远程办公制度
- **业务要求：** 结构化要点列表，覆盖申请、跨城、信息安全等核心维度

#### S5 · 合规覆盖

- **典型问题：** 知识库有没有数据出境规定？
- **业务要求：** 命中则给出条款与引用；未命中则明确说明无覆盖

#### S6 · 拒答

- **典型问题：** 员工年假多少天？（库中无内容）
- **业务要求：** 输出标准拒答文案；禁止无来源断言；禁止用预训练知识编造制度

### 2.3 不在范围

- 数值计算、TCO 推导（Demo B）
- 多 Agent 任务编排（Demo B）
- 文档权限分级、SSO、增量索引
- Ragas 全量 LLM Judge（规划 v2.0）

## 3. 产品方案

### 3.1 核心流程

```
用户问题 → 规划（拆解检索策略）
         → 检索（Hybrid + Rerank）
         → 反思（覆盖够吗？不够则补检，最多 2 轮）
         → 撰写（带引用报告）
```

| 阶段 | 职责 |
|------|------|
| 规划 | 拆解为 2–4 条检索词，覆盖问题不同侧面 |
| 检索 | BM25 + 向量 RRF 融合，Rerank 重排取 Top 片段 |
| 反思 | 评估覆盖度；对比题检查双来源；不足则补充检索 |
| 撰写 | 仅基于片段生成报告；关键结论附 `[来源: 文件#chunk]` |

**Hybrid 检索的设计依据：** 企业文档含专有名词（InsightDoc、FlowAgent），纯向量对「产品 A」类口语表述 recall 偏低；BM25 补关键词命中，RRF 融合兼顾语义与字面匹配。

### 3.2 方案对比

| 方案 | 优势 | 局限 |
|------|------|------|
| 关键词搜索 | 精确、快 | 无法跨段综合 |
| 单轮 RAG | 实现简单 | 复杂问题 recall 低，无纠错 |
| 开放式 ReAct | 灵活 | 难系统化评测 |
| **本产品** | 反思补检 + 引用规范 + 可评测 | 不支持计算与多 Agent |

## 5. AI 质量要求

### 5.1 检索质量

- Hybrid（BM25 + 向量 RRF）为默认策略
- Rerank 提升 Top 片段相关性
- 对比题：识别对比意图 → 追加定向 query → 反思检查双来源

### 5.2 生成质量

- 仅基于检索片段生成，禁止编造
- 数值与条款 grounded 于片段
- 输出结构：结论 → 依据要点 → 引用列表

### 5.3 拒答策略

- 无法支撑结论时输出「未找到」「知识库中未」等标记
- 禁止用预训练知识回答企业制度

### 5.4 评测体系

封闭评测集 **60 题**，覆盖流程、对比、条款、摘要、合规、拒答。自动化输出四维指标。

| 版本 | 关键增量 | Recall@5 | 题量 |
|------|----------|----------|------|
| v0.1 | 纯向量 + 基础流水线 | 80% | 5 |
| v0.2 | Hybrid + Rerank | 100% | 30 |
| v1.0 | 反思补检 + 60 题评测 | 100% | 60 |
| v1.1 | Bad Case 修复、引用规范 | — | — |

**质量边界：** Faithfulness 为启发式校验；知识库仅 5 份文档，泛化性有限。

### 7.2 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 专有名词语义 gap | 对比题 recall 下降 | Hybrid + 对比策略 + 反思双来源检查 |
| API 不稳定 | 规划/反思失败 | 自动重试 |
| 启发式 Faithfulness 偏差 | 指标不代表真实体验 | v2.0 LLM Judge |
| 知识库规模有限 | 泛化不足 | 扩库 + 权限 |

**关联产品：** Demo B 复用本知识库，承担「检索 + 计算 + 报告」复合任务。
